# 隐藏桌面任务执行链路

工作台的 `workbench-apps / local-workspace:apps` 由生产 `TaskDesktopSessions` 注册 `WorkbenchTaskExecutor`。选择已保存、已确认的任务应用并发送任务后，后台按登记 ID 固定应用身份与版本；原有 `TaskAppOnboarding` 完成受控无参数启动及归属验证，由启动签发者一次性交接原始回执。任务 Session 身份与应用预留身份分别核对，不用 PID、窗口句柄或路径代替启动来源证明。

私有 Python 管道提供原窗口的 UIA、截图、定位及定向动作。规划、Graph 风险门、模型预算、动作日志、独立核验、人工结果复核和 Workflow 学习继续使用现有内核。HTTP 可选字段 `appBindingId` 仅选择当前环境的登记项，不能携带路径、启动参数、目标回执或输入凭证；Host/Guest 协议与 Workflow schema 不变。

动作执行前重新解析定位，使用短期一次性观察引用，并核对原进程、窗口、Job、Windows Session、Desktop、安装指纹和输入权。效果提交与登记撤销通过现有 SQLite 登记事务串行化。输入权在管道读取线程续租和撤销，实际原生工作在单线程队列串行执行。撤销立即失效，排空后才 ACK；超时、未知效果或动作 ID 冲突不自动重发。同一动作 ID 的结果被保存，视觉 Runtime 透传该 ID。

当前定向机制为窗口消息点击、双击、单键和纵向滚动，以及 UIA ValuePattern 文本输入；不使用系统全局输入、共享剪贴板或切换用户桌面。仅执行原始主窗口及其 Job 内子控件，不重新绑定替代窗口。窗口消息与 UIA 是否被某个应用接受，由真实目标和独立观察判定，不把机制声明当作任意应用兼容证明。

原有边界保持：从资源预留起最多 60 秒、输入租约 3 秒、256 次动作、单次文本 512 字符、UIA 枚举 1000 项、待处理原生请求 16 个、管道报文 128 KiB、截图 4 MiB 和 2048 像素边长。模型全局/单次预算未提高。暂停或等待用户会释放输入权，现场仅保留至原到期时间；继续必须复查原回执并取得新输入权。终态清理确认 Job 内进程归零和 Desktop 消失，清理结果单独记录；失败不能改写为通过，已确认清理的旧 Session 不触碰新应用资源。

使用方式：选择 Hidden Desktop → 添加或选择已确认应用 → 设置模型 → 自主模式输入目标 → 发送任务。单独的「打开应用」仍是应用预览入口，已打开的资源需先关闭或等待到期，再提交新任务。保存、选择、刷新及重启本身不启动应用。辅助模型默认关闭，实机业务结果仍须由操作者验收。

初始交付按用户要求只做代码静态检查、基础启动及只读 HTTP 检查，未提交真实任务或执行网易云收藏。后续用户明确授权实际执行《甲乙丙丁》收藏任务，测试结果与修复见下文。历史 A5 safety FAIL 与整体未完成状态保持。

基础检查结果：修改的 TypeScript/JavaScript 可解析，两个 Python 文件通过 AST 解析；普通启动入口 `src/app/start.ts --port 4173` 成功，页面、任务脚本、应用脚本及环境目录均返回 HTTP 200，环境目录将隐藏桌面登记为 `executable: true`。这只确认启动与装配，不是任务执行验收。

用户实测曾在应用启动验证完成、模型调用为 0 时遇到 `workbench-native-operation-failed`。检查发现原窗口首次绑定在设置本次 Job 查询域之前调用归属校验；常规尺寸窗口没有经过 fit/preview 的 Job 设置，或仍保留上一启动的 Job 名称，导致自有窗口被拒绝。现先绑定经过启动归属验证的本次 Job，再执行相同的原窗口校验，保留全部拒绝条件。串行原生请求的错误现在记录操作名、异常类型和数字系统错误码，将稳定的隔离拒绝原因透传为具体错误，不输出任意异常文本。连接失败时关闭原 Session 并回收其已绑定的自有资源，清理失败合并报告，不伪造任务结果。本次修复仍只做语法与基础启动检查，不自动重跑用户任务。

后续整链路静态复查补齐以下衔接：

- 原生客户端的并发请求共用初始化 ACK，关闭开始后拒绝新请求；初始化失败终止工作进程。请求端也遵守原 128 KiB 上限，关闭异常仍结束管道并等待退出。
- 任务队列线程独立设置 DPI，保证窗口矩形、截图和定向坐标一致。窗口枚举直接使用自有 Desktop 句柄，保持控制线程在 Default，不在 UIA 已持有 COM 对象时临时重绑线程桌面。
- 执行准入使用只读目标状态查询，不重复初始化 UIA；动作准备仍解析实际控件，效果提交处仍检查两秒观察引用、原目标和输入权。只读文本控件在提交前拒绝，恢复观察拒绝其他 Desktop 或捕获世代，复用动作回执时释放多余定位对象。
- 输入权获取失败会清理已经连接的 Session，旧租约的迟到续租错误不污染新租约。关闭先即时失效本 Session 的原生输入，再串行排空与清理；撤销异常仍尝试回收，但整体保持失败，不恢复输入许可。多 Session 的原生关闭串行排队，避免自身超过队列上限。
- 到期线程通过独立 Job 句柄锁先失效输入并终止本次自有 Job，再等待原生队列清理；长 UIA 调用不延后资源终止。句柄释放与到期终止互斥，旧到期处理不得清理后来创建的资源。
- 排队时已选择的应用若发生登记变化，错误写回原交互并要求新任务，避免永远显示运行中。刷新环境/模型配置不再清空同环境的应用选择；刷新应用后仅恢复仍在当前登记列表里的选择。

既有合成夹具同步适配了只读 Session、串行管道 ACK 和控制线程保持 Default 的行为。静态复查交付时仅解析源码并验证普通服务启动与只读接口；后续定向测试记录如下。
