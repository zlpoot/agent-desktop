---
name: lab-tasks
description: Run registered Agent Desktop labs tasks through MCP, inspect execution and verification, and release the session. Supports synthetic forms and explicitly authorized CloudMusic fill/readback or submit-search/read-results profiles, without playback or favorites.
---

Choose the server matching the user's request: `agent_desktop_lab` for synthetic tasks; `agent_desktop_lab_real` for explicitly authorized CloudMusic fill/readback; `agent_desktop_lab_search` for explicitly authorized search submission and reading results. Never switch modes as a fallback. If tools are missing, report that Codex MCP needs restarting; a shell client is not native tool validation. Use `capabilities_list` and `capability_describe` to discover the configured task and inputs. Prefer the registered workflow for a complete task. Report the actual mode and verification scope.

Call `session_open` before `task_start`. Its lease starts now, not when MCP connects. Repeating open while active returns the same session without renewing it. Call `task_start` with the registered `capabilityId`, business `inputs`, and a request ID chosen once for this user action. Keep the returned `jobId`. The receipt means accepted, not completed. Query `task_status` until execution finishes; space repeated queries rather than busy polling.

If the start response is lost, repeat the same request ID and identical inputs on the same connection. A new request ID may repeat effects. Deduplication and jobs last only for this process; after a connection restart the previous outcome is unknown, so do not silently resubmit.

Treat execution and verification separately. `verification.status=manual-required` is not automatic acceptance. `effectStatus=unknown`, failed verification, lease expiry, stale targets, or recovery-required stops the workflow. Do not retry inputs, relearn, relax matching, or start a replacement session to conceal failure. Report the job's error and known scope.

Use `observation_get` while idle. Synthetic observations prove synthetic state only. Real observations independently read the current owned search field on its UIA thread and return a captured evidence path; compare `value` to the task input. A successful fill/readback does not prove search results, playback, or general real-world acceptance. Finish with `session_close` and check `cleanup.closed`, including after errors. A busy close does not cancel the task: query its original job, then close. For the user's next distinct task, explicitly open a new session and use a new request ID. Old jobs and request IDs remain queryable/reserved on this connection. Never open a replacement session to replay a failed or unknown action. Preserve failed results.

For synthetic forms, describe `synthetic.form.submit`, then pass `inputs={"query":"Synthetic example"}`. Its dispatch requires manual acceptance even when execution is `done`.

The real profile exposes only `cloudmusic.fill-search` and its four pinned children: launch, prepareSearch, locateSearch, fillSearch. The workflow accepts `inputs={"query":"接入测试"}`, launches an owned instance in a hidden desktop, fills and verifies the search field, and does not submit search or play media. An existing user instance is refused: do not close or attach to it. Keep application identity, learned hashes, budgets, lease, and stale-target checks intact; do not relearn automatically. Application-managed network activity is not isolated by this profile. It grants no model execution capability.

The separate search profile exposes `cloudmusic.search` and six children, adding submitSearch and readSearchResults. Its inputs are `song` and `artist`; the existing JSON joins them into the query. For example, use `{"song":"甲乙丙丁 (你我怎么两清)","artist":"李佳薇"}`. Submit only once, then wait on the same job. The reader reuses only the pinned read-only readiness predicate from the existing song-opening JSON; song opening, playback and favorites are excluded. `manual-required` remains after result matching. Use `observation_get` to obtain current `results.rows` with actual title/artist names and screenshot evidence. The result scope is the first matching candidate and related artist in the declared region, not the entire search result list or global uniqueness. After the result reader's declared page transition, `value` may be null because input bindings were released; use actual result rows as the result evidence. A timeout or missing/mismatched result is failure, not permission to resubmit or fabricate an empty success. Close the session after verification.
