## 1. 产品目标、关键边界

Agent Desktop 是以任务和可复用能力为中心的桌面 Agent 产品。用户描述目标，系统在被明确选择的环境中观察、定位、执行、验证，记录证据；成功任务可以产生 Workflow 候选，经过独立验证与批准后才能发布和回放。页面以任务闭环为中心，而不是以 Chrome、VM、Win32 夹具或测试场景为中心。

- **按最终产品设计**：工作台、任务、工作流、环境与应用、设置五个导航入口保持稳定，Chrome/VM/Physical/Hidden Workspace 都是运行环境与能力声明，不是各自的一套产品 UI。
- **一个 Task 系统、多种执行策略**：稳定、自主、学习、优化是同一套任务运行与 Workflow 生命周期的不同策略；不为每种模式另造状态库、审批、历史列表或页面。
- **功能与呈现分离**：页面提供终局设计的结构；尚无可信能力的功能应显示不可用原因或“规划中”，不能用一个可点的模拟按钮制造执行成功的印象。
- **真实事实优先**：真实 Task、执行/验证/清理、人工反馈、Workflow candidate/verified 分开描述，系统接收到“动作已派发”不等于任务 PASS。
- **外部系统与自研边界**：不在 UI 阶段重做 Windows Hidden Desktop 内部隔离测试；仍需正确呈现本项目的目标绑定、异常和资源生命周期事实。
- **保留旧记录**：#48 的 Hidden Chrome 真实结果与 Workflow 候选是可用于页面只读回读的证据，但绝不因查看页面自动创建新的 Key 或回放含副作用的 Workflow。
- **复用现有产品实现**：不修改 Agent Loop、Guest 协议、Provider Contract、Workflow Schema 或现有风险门；这次以 DOM/样式/交互编排为主。

## 2. 统一的信息架构

一级导航固定为五区，路由名称可沿用已有内部标识，用户可见的中文名称如下：

| 一级导航 | 首屏重点 | 核心操作 | 不属于该页的事项 |
| --- | --- | --- | --- |
| 工作台 | 目标、执行模式、环境与任务现场 | 创建/提交任务、查看进度、处理授权/介入、打开结果 | 长期流程版本管理、调试配置 |
| 任务 | 当前任务与历史 Task/Run | 筛选、查看步骤、证据、状态和失败、人工反馈 | 单独重新派发已完成动作 |
| 工作流 | candidate/verified/retired、流程版本与参数 | 搜索、查看、无副作用预览、合法试运行/发布 | 未授权的新 Key 创建，后台不支持的任意回放 |
| 环境与应用 | Physical、VM、Hidden Workspace 统一列表 | 选择环境、连接状态、应用发现、配置、能力可用性与原因 | 将环境显示成“自动拥有全部输入能力” |
| 设置 | 模型、预算、提示词、权限、扩展、隐私 | 配置已有后端支持的选项、查看日志与设置来源 | 没有 API 却伪造可保存的设置 |

- 左侧导航永远是产品导航，而不是“桌面应用类型”导航。**环境与应用**合并为一个一级入口，页内可设置“环境 / 已接入应用 / 能力”子视图。
- 工作台默认显示“新任务 + 最近任务 + 当前执行状态”。选中任务时切为“现场 + 步骤 + 右侧运行上下文”。
- 任务详情与工作台共享同一 Task ID 和同一事实源；从任务列表返回工作台不重新创建 Task。
- 工作流中心显示已保存的候选与版本；目前的 Hidden Chrome 15 步 candidate 必须显示 **未回放 / 不可通过通用执行入口运行**。
- 设置页保留当前预算、提示词、插件真实入口；模型提供方、主题等未来配置可出现在规划说明中，不能冒充持久化功能。
- 旧 URL 兼容：已有的工作台、任务、流程库、桌面、应用管理、设置 Hash 链接需解析为新五区导航；旧 Task 深链接应仍能打开同一历史记录。

## 3. 任务模式与运行能力模型

| 模式 | 产品含义 | v0.1 页面策略 | 实际启用门槛（未来） |
| --- | --- | --- | --- |
| 稳定 | 匹配并只执行已验证 Workflow | 展示模式和 Workflow 选择；不支持的目标禁用执行并解释 | Verified 版本、环境/参数匹配、风险授权与目标回放能力 |
| 自主 | 模型根据当前观察规划下一动作 | 展示模式及模型/预算说明；仅对实际支持的 Runtime/模型组合开放 | 模型连接、可执行的受限 Runtime、目标绑定和独立验证 |
| 学习 | 对陌生任务探索并生成候选 Workflow | 展示学习产物、来源 Task 与 candidate；无学习执行适配时标“待启用” | 真实探索证据、可信轨迹、候选构造及人工确认 |
| 优化 | 基于运行证据改进现有 Workflow | 工作流版本对比/优化入口有位置，未实现时为只读说明 | 新旧版本对照、真实结果验收、可回滚版本化流程 |

**状态驱动的选择原则**：模式选项可以被查看，但当选中一个后端不支持的模式时，不显示“开始执行”的可操作按钮；改为说明哪个前置能力缺失。不要将一个“固定场景可执行”自动推断为“自主/学习模式可执行”。用户可以选择当前已支持的固定场景，但固定场景应只是一个执行计划选项，不决定产品一级页面结构。

### 前端准备态（从后端事实派生，不是新的权限事实源）

- **可运行**：环境、场景/Workflow、必要配置、预算以及许可均已明确，后端报告可受理；页面允许正常提交。
- **待选择**：没有选环境、没有选需要的场景/工作流；页面提供选择路径，不自动选择第一个候选。
- **待确认**：已有真实风险/权限/副作用确认点；只显示后端实际允许的人工确认入口，不能凭 UI 本地勾选覆盖 Host 权限。
- **不可用**：模式未实现、场景不支持、目标离线或缺少能力；显示原始分类及用户可执行的恢复建议。
- **处理中**：已发出一次提交；禁用重复点击，展示 Task ID 或“结果未知，检查历史”，绝不因轮询迟到自动重复 POST。

## 4. 桌面端页面线框（信息层级，非截图）

    │ Agent Desktop        执行环境：未选择 / 已连接 / 不可用       任务状态       设置 │
    ├───────────────┬───────────────────────────────────────────────┬───────────────────┤
    │ 工作台        │  今天想让 Agent 做什么？                      │ 最近任务 / 提示    │
    │ 任务          │ ┌───────────────────────────────────────────┐ │ 当前任务状态      │
    │ 工作流        │ │ 请输入目标，或选择已验证 Workflow…        │ │ 需要人工处理      │
    │ 环境与应用    │ └───────────────────────────────────────────┘ │ 执行环境状态      │

    │               │──────────────────────────────────────────────│                   │

宽度建议：左导航 216–232px；内容区域 minmax(0,1fr)；右侧上下文 320–360px；列间距 12–20px。右侧可折叠，并始终保证输入区域、目标选择与实际提交按钮可见。

**交互**：目标输入框优先、模式信息次之、环境明确选择、后端 readiness 提示最后才允许提交。不能把“只读有限场景”的状态写成通用自主任务可执行。

### 4.2 工作台 · 执行中

    ┌───────────┬───────────────────────────────────────────────┬────────────────────┐
    │ 一级导航  │ 正在执行：任务目标 / 环境 / 来源 / 耗时         │ 当前步骤           │
    │           │ ┌───────────────────────────────────────────┐ │ 模型/预算或规则    │
    │           │ │ 现场视图                                  │ │ 待批准动作         │
    │           │ │ 浏览器 DOM / 原生图像 / UIA / 不可用原因  │ │ [暂停][继续][停止]│
    │           │ └───────────────────────────────────────────┘ │ 资源清理与风险提示 │
    │           │ 步骤 1 观察 → 定位 → 动作 → 独立验证           │ 最终文件 / 候选    │
    │           │ 步骤 2 … / 暂停 / 失败原因                     │                    │
    └───────────┴───────────────────────────────────────────────┴────────────────────┘

**现场类型与真实性**：
- Browser 页面、Windows/VM/Hidden Workspace 的实时帧或历史证据来自当前已有 Provider 能力及记录。没有画面时显示“本环境暂无可用现场视图”，不能用占位图冒充实时截图。
- 画面已过期时标注“过期 + 最近时间”；历史截图一律带“历史证据”字样。
- Pause/Take Control/Resume/Stop 由后端控制和场景 capability 决定是否显示、可点及原因。无法接管的受限 Chrome Task 不能出现可点击的“接管”。
- 观察、动作派发、独立验证、Cleanup 是彼此独立的事实。派发完成但验证未知时，明确标“结果未知，不自动重放”。

### 4.3 任务页（运行记录 + 明细）

    左栏：搜索 / 状态筛选 / 时间排序 / Task 列表
    中栏：目标、执行环境、状态、任务阶段、步骤时间线、实际结果
    右栏：选中步骤的观察、动作、验证、证据、耗时及关联 Workflow

详情优先按“目标是什么 → 实际做了什么 → 得到什么结果”组织，不把 Host/Guest 诊断和原始 JSON 常驻首屏；诊断数据放在可展开的技术详情。**Owner 人工验收**与**自动完成验证**分为两个来源字段；如果后端尚无可追溯人工验收记录，就显示“暂无可读取的系统内人工验收记录”，不据此否认外部 Owner 报告，也不自行把固定标签改成 PASS。

### 4.4 工作流页（候选/已验证/已停用）

    左栏：筛选、搜索、Workflow 列表与版本
    主栏：名称、用途、来源 Task、步骤序列 / 条件、参数、风险及变更
    右栏：版本状态、运行记录、预览、试运行资格、发布与回退

- Candidate：明确“已记录，尚未证明可回放”；可以只读查看与无副作用预览，但不得因后端通用 Browser 入口存在就自动启用 Hidden Chrome 候选执行。
- Verified：展示成功验证次数、目标环境、版本与可信执行入口；回放时仍核对当次环境、参数与权限。
- Retired：保留审计和历史，不提供直接启动。
- 预览输出包含“将执行的步骤 / 将修改的文件 / 需要再次授权的动作”；预览绝不发生真实输入或创建。
- 首次 Key 创建工作流有非幂等副作用，不能用第二次生成 Key 来验证 UI，也不自动晋升为 Verified。

### 4.5 环境与应用页

    环境卡：名称 / Provider kind / 当前可用性 / Session / 明确能力与限制
    ├─ Physical Desktop：仅显示真实已注册能力
    ├─ Virtual Machine：未连接时给出准确原因，不假设 VM 正在运行
    └─ Local Workspace：Hidden Chrome / fixture / 其它可用适配
         └─ 环境内应用：已发现 → 已确认 → 已验证启动 → 可操作能力
    应用详情：安装信息（脱敏）/ 当前配置版本 / 匹配环境 / 能执行的有限动作

使用同一列表和筛选机制承载各种环境，避免“VM 未连接”成为所有环境的全局错误。打开应用只在对应真实后端能力和授权存在时可用，发现应用、确认应用与任务执行互不自动升级权限。

### 4.6 设置页

- 当前可用：默认预算、提示词配置、现有插件与扩展状态（沿用真实 API）。
- 预留但不可伪保存：模型提供方、默认模式、隐私和文件策略、外观、执行环境偏好。
- 设置页面显示“当前生效于本机 / 仅供未来版本规划 / 需重新配置”来源与生效范围；不要为未存在的 API 提供乐观成功提示。

## 5. Task 状态与证据的呈现合同

**任务状态**从现有 Task 事实派生，不新造一个互不兼容的业务状态机：

| 业务含义 | 页面文案 | 必须同时显示 |
| --- | --- | --- |
| queued / preparing | 排队中 / 准备中 | Task ID、环境与是否取得输入权 |
| running | 执行中 | 当前观察/动作及最近验证阶段 |
| waiting_user | 等待人工处理 | 原因、可用审批入口、后端允许的下一动作 |
| paused | 已暂停 | 是否有未确认动作、能否 Resume、是否需要新 Task |
| verifying | 正在验证 | 动作派发与独立结果尚未确认的区别 |
| done / completed | 已完成 | 执行、验证、清理分别呈现 PASS/UNKNOWN/FAIL |
| blocked / failed | 已阻断 / 失败 | 本次已/未发生实际副作用、处理建议、不可重放原因 |
| stopped | 已停止 | 清理是否完成、是否有遗留或不确定资源 |
| unknown / missing proof | 结果未知 | 明确说明不自动再执行非幂等动作 |

不同后端可能使用 done、failed、paused 等既有状态与 desktop_scenario_* 阶段事件；前端只做统一文案与 UI 呈现，不反向修改历史 Event 或 Host 状态。结果与清理必须分别显示；“清理 PASS”不等于目标动作 PASS。

**能力展示**保留 supported / unsupported / not-proven / forbidden 与当前 readiness 的差别，且区分“Provider 理论支持”与“这个应用/此 Session 当前能用”。页面不可根据环境 kind 自动扩大能力。

## 6. 视觉设计系统与可访问性

### 6.1 布局与颜色

- 视觉气质：深色优先、低噪声、应用控制台风格。保留现有深色语义，避免用过亮的彩色大卡片造成误导；深浅色主题可作为设计 token 规划，但 v0.1 的切换控件须在真实实现后才能提供。
- 颜色分工：中性色用于区域层级，低饱和主色用于唯一主操作；成功、警告、失败仅用于真实状态反馈，禁止以纯颜色承载唯一信息。
- 字体：系统 UI 字体与中文可读字体优先；主体 13–15px，关键标题 19–24px，辅助状态 11–12px，代码证据采用等宽字体。
- 组件统一：导航、任务卡、模式选择、环境选择、时间线、能力状态、步骤抽屉、审批面板、Workflow 列表/详情、空态、结果摘要、诊断折叠区、Toast/inline error。
- 状态文字应可复制、不因截断丢失关键错误码；技术 ID 放在 secondary 文案或详情里。

### 6.2 响应式规则

| 视口 | 建议布局 | 必须可用的关键操作 |

| ≥1366px | 固定导航 + 中央工作区域 + 右侧上下文 | 任务提交、审批、实时现场、结果/Workflow 查看 |
| 901–1365px | 导航可收缩，上下文可折叠；主内容弹性 | 所有提交/阻断信息无需横向遮挡 |
| 601–900px | 导航紧凑；任务主区优先，上下文转可展开面板 | 提交按钮命中、选择环境、查看批准/停止 |

针对 PR #44 的 601/668/700px 历史回归，新增测试必须检查 **elementFromPoint 按钮命中 + trusted click → submit → POST → Task ID**；不能只比较截图。建议同时用 390、900、1366、1440px 检查高度较低时滚动与 sticky 遮挡。

键盘导航遵循视觉顺序：导航 → 模式/目标 → 环境与预算 → 预览 → 提交 → 状态与结果。所有动作需 focus-visible；等待审批使用清楚的 aria-live 提示；非法输入聚焦错误字段，不因页面重新渲染抹掉任务草稿。

## 8. 组件边界和实现策略

- **AppShell**：路由、导航、当前运行环境摘要、布局；不接管任务业务。
- **TaskComposer**：目标草稿、模式/环境/应用/Workflow 选择、后端能力摘要；纯展示与明确提交。
- **ModeSelector**：共享模式定义及说明；由 capabilities/readiness 控制可用，不单独新建模式后端。
- **ExecutionViewer**：观察视图及数据新鲜度；区分 live 与历史。
- **RunTimeline / RunDetail**：步骤、动作、结果、证据、清理、模型/预算统计。
- **ActionApproval**：后端已提供的批准/拒绝或人工接管操作；不制造本地 fake approval。
- **WorkflowCatalog / WorkflowDetail**：候选、版本、参数、验证、执行预览；继续消费当前 WorkflowStore 和 API。
- **EnvironmentCatalog / AppRegistry**：Provider、Session、target/app readiness、应用发现与确认历史。
- **Status / Notice**：不同来源的 PASS/FAIL/UNKNOWN/NOTRUN、unsupported/not-proven/forbidden 文案与用户建议。

这是一套共享的表现组件与有限状态映射，不另建第二套“Agent Desktop 前端工作流”。若未来 Future UI 组件库可用，可将公共语义状态映射接到它；本版本不依赖其发布。
